★★ ① 找到并堵住了「did not become ready within 120 seconds」的**真实根因**

   该次运行**产出**的 backend/src/app.js 全文（逐字照抄，已作为测试夹具）：

       const express = require('express');
       const app = express();
       app.use(express.json());
       const columnsRouter = require('./routes/columns');
       app.use('/api/columns', columnsRouter);
       module.exports = app;

   模型只关心"把我这条需求的路由挂上去"，**把整个应用外壳删掉了**：
     · /api/health 没了
       -> 平台就绪探测永远 404（模板 README 明写健康检查就是
          `curl http://127.0.0.1:<port>/api/health`）
          => "template application server did not become ready within 120 seconds"
     · express.static(frontend/dist) 与 SPA 兜底 sendFile 没了
       -> `page.goto('/')` 404 -> 基准测试第一步 `openHome` 就挂
     · initializeDatabase() 没了 -> 数据层从未初始化

   这与「引用了不存在的模块」同类：**局部正确、整体不可运行**。
   模块图审计只看引用能否解析，**看不见外壳被删**。

   新增 factory/testaudit.audit_app_shell()，接入实施循环（回传 + 有界重试）：
     APP_SHELL_HEALTH_MISSING         缺 /api/health 或 /health
     APP_SHELL_FRONTEND_NOT_SERVED    不再托管前端（缺 static + SPA 兜底）
   只对**真实可服务的工程**生效（必须有 backend/package.json），
   避免误伤合成工作区。
   反馈明确写着「新增路由必须**追加**，不能重写整个文件」。

② 移除模板里的**游离运行产物**
   template/backend/database.db（0 字节）—— 我本地起服务验证时生成的，
   被卷进了模板，会随每次提交复制进产出。
   同时给打包器加了排除：*.db / *.sqlite / *.sqlite3 与 .arc-test-db/。
   （此前 packager 只排除 dist/ 与 node_modules/，这类文件会漏进去。）

③ 补 template/.gitignore
   与捕获到的工作区一致（ArcBench 托管块）：node_modules / dist /
   dist-ssr / coverage / *.db / .env / .arc/*（保留 traceability）。
