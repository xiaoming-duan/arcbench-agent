# 契约冻结

> 把跨模块调用约定从**提示词建议**升级为**不可篡改的验收合同**。

**形态**：DSh Tool Plugin —— 两个工具 `freeze_contract` / `verify_contract`
**验证状态**：✅ **真实运行验证** —— 全链 6/6，`CONTRACT_MISSING` **0 次误报**

---

## 为什么需要它

> **提示词约束不住模型。** 这条被真实运行确认。

某需求拿到 **3 次**依赖归因提示 + 1 次阻断理由，仍未真实集成上游。
**问题不在提示写得不好，在于提示本身不是约束。**

契约必须落成**制品 + 门禁**：

```
需求声明（人写）  --freeze_contract-->  只读合同 + sha256 侧车
                                              │
                                       提示词**只读**它
                                              │
                                    模型产出的实现 / 测试
                                              │
                                      verify_contract 判定
                                              │
                        一致 -> 放行 ; 缺失/篡改/不符 -> 阻断
```

---

## 两个工具

### `freeze_contract`

```
freeze_contract(dir, req_id, calls[], frozen_by?) -> { written, contract, record, sha256, readonly }
```

- 写出 `<dir>/<req_id>.yaml`（`frozen: true` + `integrity.sha256`）
- 写出侧车 `<dir>/<req_id>.sha256`（三行：哈希 / 冻结时间 / 冻结者）
- 两个文件均 `chmod 0444`
- **空 `calls` 不生成合同**（可选字段语义）

### `verify_contract`

```
verify_contract(dir, req_id, declared?, actual_signature?, actual_upstream?) -> { verdict, ... }
```

返回四态之一：

| verdict | 含义 | 处置 |
|---|---|---|
| `CONTRACT_MISSING` | 合同**不存在**（或未冻结 / 与声明**漂移**） | 阻断 |
| `CONTRACT_TAMPERED` | 合同**存在但被改过** | 阻断 |
| `CONTRACT_MISMATCH` | 合同**未被改**，但**实现/调用**不符 | 阻断（可重试） |
| `CONTRACT_OK` | 一致 | 放行 |

**MISSING 里含漂移**：合同文件原封不动、但需求声明变了 ——
「声明改了而合同没重新冻结」与「合同被改」是**两件不同的事**，故分开判定。

**判定顺序：篡改优先于漂移** —— 文件被改时报更具体、更可操作的结论。

---

## 不可编辑性：三层，缺一层就漏一种情形

| 层 | 手段 | 覆盖范围 | 作用 |
|---|---|---|---|
| 权限位 | `chmod 0444` | — | 让「随手改」不容易发生（**纵深防御，不是安全边界** —— 同用户可 `chmod` 回来） |
| 内嵌 | `integrity.sha256` | **正文** | **可移植**：合同单独拿走也能自证 |
| 侧车 | `<req>.sha256` | **完整文件字节** | **权威**：连「只改 integrity 字段」也能发现 |

**为什么两路都要**：内嵌字段**无法覆盖自身** —— 哈希写进文件后再算哈希，值就变了（**自指无解**）。
所以内嵌只能覆盖正文，用于可移植自证；「连 integrity 字段一起改」由侧车兜住。

---

## 两条实现纪律（缺一即失效）

### ① 生成与校验必须共用同一个哈希函数

两边各写一套口径是这类校验**最经典的失效方式**：
生成时算 A、校验时算 B，于是永远不等（误报）或永远相等（漏检）。

本包的 `lib/contract.js` 就是那个共用函数，**不要在任何地方复制它**。

### ② 不得保留「读不到合同就回退到需求声明」的旁路

保留回退等于：合同缺失时提示词仍拿到内容，**表面正常而「冻结」未生效**。

**实测中正是这个形态**：读路径因一层多余的 `.parent` 失效 → 静默回退到内存声明 →
提示词内容**恰好相同** → 看起来一切正常。

```
合同写出来了          ✅
门禁 contract_ok=True ✅
提示词里有合同内容    ✅（来自内存声明）
「冻结」这一性质生效  ❌ **从未生效**
```

**只读日志与报告会得出「契约冻结已生效」的错误结论。**

## 输出示例

```json
{
  "verdict": "CONTRACT_TAMPERED",
  "req_id": "REQ-11",
  "expected_sha256": "40f42ea40a48fd30…",
  "actual_sha256": "beaaf0a28f693dc6…",
  "frozen_at": "2026-10-03 20:41:07",
  "detail": "合同在冻结后被修改 —— 期望 40f42ea4… / 实际 beaaf0a2…（冻结于 …）。合同是验收依据，实现阶段不得改动它。",
  "fix": "不要编辑合同文件。若确需变更契约，请改需求声明后**重新冻结**（会重算哈希）。"
}
```

**拒绝理由必须含三项**：期望哈希 / 实际哈希 / 冻结时间戳，外加**可执行的修正指令**
（不只是说错了，还要说下一步做什么）。

## 与其它组件的关系

| 组件 | 关系 |
|---|---|
| UI 契约提取 | 并行：一个管**模块间 API**，一个管**页面上有什么** |
| 五道门禁 | 上游：`verify_contract` 是其中「契约门」的实现 |
| 分类型重试预算 | 下游：`CONTRACT_MISSING`/`TAMPERED` 只给 **1** 次重试（改实现修不好）；`CONTRACT_MISMATCH` 给 2 次 |
