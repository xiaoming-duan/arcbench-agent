arcbench-agent v10 —— 交付标签（诚实标注）
============================================================

相对 v9 的变化
------------------------------------------------------------

① 就绪探测面加宽 + 消除「永远不就绪」的陷阱
   平台报错（本次）：
     template application server did not become ready within 120 seconds
     （注意：与之前那条 "exited before becoming ready (code=1)" **不是同一个错误** ——
       这次不是崩溃，是**等不到就绪**。同一个 run 里另外两条是
       "Generation agent finished successfully" 与
       "traceability artifacts are expected to be written directly by the SDK"，
       即 agent 本身跑完了。）

   实测（本地，逐路径探测）：
     frontend/dist 存在  ->  / 200   /api/health 200   /health **404**  /healthz **404**
     frontend/dist 缺失  ->  / **503**  /api/health 200   /health 404
   => 两个确凿的「永远不就绪」来源：
      a) `/health`、`/healthz` 是 404 —— 探测若用这两条路径，永远不会就绪
      b) 无 dist 时 `/` 恒回 **503** —— 探测只认 2xx 的话，同样永远不就绪，
         而且**真正原因（前端没构建）被完全掩盖**

   改法：
     · 新增 `/health` 与 `/healthz`（与 `/api/health` 同返回 200 JSON）
     · 无 dist 时 `/` 由 503 改为 **200**（页面内容仍如实说明构建缺失）
   实测（改后，两种情形）：
     /  /api/health  /health  /healthz   全部 **200**
   「就绪」与「正确」是两件事：改后前端没构建的问题会暴露在**基准测试**里，
   那才是该暴露它的地方；而不再伪装成"服务没起来"。

   回归守卫：tests/test_playwright_e2e.py 新增 3 项（共 14 项）——
     常见就绪路径齐备 / 无 dist 不得回 503 / listen 不得误绑 127.0.0.1

附带更正（承接 v9 标签）
------------------------------------------------------------
· **端口不是错配**：平台注入 PORT，我们的默认值被覆盖。
· **frontend 构建很可能冗余**：平台 runner 自己会跑 frontend-npm-build。
  但 ① 的 503->200 仍然有意义 —— 它保证「构建失败」不会伪装成「服务没起来」。
